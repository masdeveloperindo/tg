## Yang diuji

- **Struktur:** 30 tabel domain, InnoDB dan charset utf8mb4; seluruh 15 kolom DECIMAL memiliki precision/scale sesuai kontrak dan tidak ada FLOAT/DOUBLE. Nilai besar dan pecahan uang/lot round-trip sebagai string.
- **Waktu:** seluruh kolom waktu domain DATETIME(6), tujuh tabel created-only tidak memperoleh updated_at. Model mempertahankan microsecond, menormalisasi instant WIB ke UTC dan tidak menggeser kolom DATE.
- **Relasi:** set lengkap 38 FK dibandingkan dengan kontrak, termasuk target id/delete rule. Setiap FK diuji insert ke parent hilang (MySQL1452/SQLSTATE23000); histori keuangan RESTRICT dan dua log opsional SET NULL.
- **Invariant:** semua 25 CHECK enum menerima nilai sah dan menolak token invalid/uppercase/aksen; CHECK uang/tanggal/rating serta 22 unique key diuji dengan penolakan database. Generated column membatasi satu versi aktif per produk tanpa melarang beberapa versi nonaktif. Lisensi revoked tetap tidak dapat diduplikasi; order renewal mereferensikan row yang sama.
- **Model:** semua 30 model dapat dihidrasi; enam field sensitif terenkripsi di database dan hidden dari serialisasi. Email dinormalisasi, password Argon2id, role/status tidak dapat dinaikkan melalui mass assignment. Tidak ada implementasi endpoint autentikasi pada task ini.
- **Histori:** koreksi rebate memakai entri signed baru; Eloquent menolak update/delete/quiet/bulk/upsert/updateOrInsert/increment pada rebate dan activity log. Raw SQL eksplisit tetap di luar batas model; ini bukan klaim DB trigger immutable.
- **Wallet:** dua koneksi MySQL nyata diverifikasi memiliki connection id berbeda. Koneksi kedua gagal mendapatkan wallet yang sudah di-lock (1205), lalu berhasil setelah transaksi pertama rollback. Ini bukti anchor row lock, bukan bukti race workflow saldo/penarikan yang belum dibuat.
- **Seed:** seeder default diuji tidak membuat akun, data domain atau secret di seluruh 30 tabel. Fixture sintetis hanya dipakai suite pada `tg_test`.

## Indeks dan EXPLAIN

`DomainIndexTest` memasukkan 100 pengguna sintetis serta 1.000 baris per tabel orders/licenses/trading_accounts/rebate_entries/withdrawals/license_logs dalam transaksi test yang di-rollback. Enam query menggunakan filter kontrak:

| Tabel | Indeks yang harus dapat dipertimbangkan optimizer |
|---|---|
| orders | `(status, expires_at)` |
| licenses | `(user_id, status, expires_at)` |
| trading_accounts | `(user_id, status)` |
| rebate_entries | `(trading_account_id, period)` |
| withdrawals | `(user_id, status, created_at)` |
| license_logs | `(license_id, created_at)` |

EXPLAIN harus memuat indeks terkait sebagai candidate, memakai akses indexed `ref/range/const` dan mengestimasi kurang dari seluruh 1.000 baris. MySQL boleh memilih indeks selektif lain dengan prefix setara, misalnya unique license triple berawalan user_id. Tes tidak memaksa indeks atau menganggap pilihan optimizer yang setara sebagai cacat. Ini validasi rencana query dataset lokal, bukan benchmark produksi.
