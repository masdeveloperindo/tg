## Cakupan yang dibuktikan

- Registrasi name/email/password+confirmation dan kontak Telegram/WhatsApp tervalidasi; email lowercase/unique, Argon2id, kontak encrypted+hidden, role/status dari browser diabaikan. User/wallet/audit berada dalam transaksi. Client tidak memiliki langkah email verification atau 2FA.
- Login disabled/salah/tidak ditemukan memberi pesan sama. Budget gagal 5 email+IP dan 20 IP selama900detik memakai key hashed; mengganti email/IP dan waktu diuji. Sukses tidak menghapus budget serangan IP. Registration/manual reset/password change juga memiliki pembatasan pada service.
- Login/OTP/password change merotasi sesi; logout invalidasi sesi dan token CSRF. Password change membuktikan password saat ini dan mencabut sesi DB lama. Client dengan password sementara dipaksa menggantinya sebelum akses member/aksi private.
- TOTP SHA1/30detik/6digit diuji dengan keenam vektor resmi RFC6238 8digit dan turunan6digit, timestamp64bit, window±1 dan inputinvalid. Secret CSPRNG160bit disimpan hanya setelah OTP benar, terenkripsi dan hidden. Counter monotonic peruser di bawah cache lock + transaksi/rowlock mencegah replay lintas sesi; gagal menyimpan counter ditolak.
- 10 recovery code CSPRNG128bit ditampilkan sekali dan disimpan sebagai SHA256; rowlock+used_at membatasi satu pemakaian dan pemilik. Kode/secret/password tidak disimpan sebagai properti snapshot Livewire atau audit plaintext.
- Password admin saja belum berhak ke panel. Setup memerlukan password login≤10menit; challenge belum terverifikasi memerlukan login password≤30menit. Sesi admin terverifikasi memakai idle≤30menit, dengan marker userid/waktu valid; expiry berlaku juga di setup/challenge/password dan direct service sehingga OTP baru tidak dapat menghidupkan sesi expired.
- Reauth memerlukan password dan TOTP/recovery yang belum dipakai. Rantai password login+OTP baru membentuk reauth sesi itu saja, berlaku≤10menit; field timestamp DB tidak memberi hak ke sesi lain.
- Policies menguji owner client A/B, admin belum/terverifikasi, disabled/forcedpassword, lease/waktu malformed/future/stale, download lisensi active dan belumexpired. Tidak ada `Gate::before` yang meloloskan seluruh aksi admin. Action bisnis yang belum diimplementasikan tetap tidak memperoleh izin otomatis.
- Reset manual hanya untuk client, lewat admin terverifikasi+recentreauth, kontak terdaftar yang bisa ditinjau di modal, alasan dan dua pemeriksaan manual. Password acak ditampilkan sekali melalui privateGET, sesi client lama dicabut dan must_change_password aktif. Tidak ada Telegram/email/WA otomatis. Audit memuat actor/subject/requestid/verificationflags tanpa credential/kontak/rekening/bukti identitas.
- UI Livewire nyata mempunyai validation inline, loading server, modal reset keyboard/focus, halaman recovery/password sementara sekali baca dan logout POST/CSRF. Rootweb wrapper memasang no-store pada respons update JSON yang sebenarnya, bukan hanya response middleware simulasi Livewire.
- `tg:create-admin` hanya membuat admin pertama melalui input password CLI tersembunyi, tidak menerima argumen password, menolak akun admin kedua dan menulis audit. Tidak dijalankan untuk membuat admin nyata; hanya diuji dengan fixture sintetis.

## Diagnosis integrasi

Review menutup jalur challenge yang semula dapat memverifikasi ulang sesi admin idle tanpa password baru. Review juga menemukan bahwa response middleware persistent Livewire dibuang oleh framework; wrapper pada web update nyata kini memasang header no-store. Dua masalah Blade pada mask email (`@{{` dianggap escaped echo) dan directive inline diperbaiki, lalu modal/aksi reset diuji ulang. Fixture pergantian admin dan request session Livewire diselaraskan tanpa melemahkan guard produksi. Smoke batch kosong awal ditolak404 sesuai guard Livewire; smoke ulang memakai snapshot komponen valid dan berhasil.
